# 开发、上架与维护成本测算

- 版本：v0.1
- 日期：2026-11-05
- 口径：只算**软件本身**的开发、部署、上架合规和技术维护
- 不含：摄影师、化妆师、客服、商家 BD、市场投放、服装采购、清洗物流、押金资金成本、办公场地等业务运营成本

> 以下为 2026 年中国大陆市场的量级估算，价格为区间，受城市、团队、需求变更和合规要求影响。不是报价承诺，也不是法律意见。

---

## 0. 先看结论

| 方案 | 范围 | 开发周期 | 一次性开发 | 首年总投入（含合规/云） |
| --- | --- | --- | --- | --- |
| A. 精益 MVP | 小程序 + 商家 H5 + 运营后台 + 后端 | 3–4 个月 | 25–45 万 | **30–60 万** |
| B. 标准全端 | 小程序 + Flutter iOS/Android + 后台 + 商家 + 基础社区 | 6–8 个月 | 60–110 万 | **75–150 万** |
| C. 自建团队 | 同 B，自己招 6–8 人做 | 6–8 个月 | 100–160 万 | **110–180 万** |
| 后续年度维护 | 云资源 + 技术维护 + 合规 | — | — | **20–50 万/年** |

**建议**：第一版先做 A，把“租衣 + 摄影预约 + 订单/押金/物流 + 商家端”跑通；App 和社区放二期。这样最容易把首年现金投入控制在 **30–60 万**。

## 1. 开发成本明细

### 方案 A：精益 MVP

范围：微信小程序、商家 H5、运营后台、后端 API；不含 App、不含完整社区。

| 模块 | 费用（万元） | 说明 |
| --- | --- | --- |
| 产品/原型 | 1.5–3 | 需求梳理、流程图、页面原型 |
| UI/视觉 | 1.5–3 | 小程序 + 商家端 + 后台 |
| 微信小程序 | 5–9 | 首页、租衣、摄影预约、订单、支付、押金、物流、我的 |
| 后端 API | 8–14 | 用户、商品、库存日历、订单、支付、押金、物流、商家、结算 |

周期：3–4 个月，4–6 人。

### 方案 B：标准全端

范围：小程序 + Flutter iOS/Android + 后端 + 后台 + 商家端 + 基础社区。

| 模块 | 费用（万元） | 说明 |
| --- | --- | --- |
| 产品/原型 | 3–6 | 多端流程、社区规则、会员 |
| UI/视觉 | 3–6 | 多端设计规范 |

| App（Flutter，iOS+Android） | 15–30 | 一套代码，含上架适配 |
| 后端 API | 15–28 | 多端统一 API、社区、消息、分账 |
| 管理后台 + 商家 H5 | 8–15 | 内容审核、营销、数据看板 |
| 测试/PM/DevOps | 6–10 | 多端兼容、支付/库存/上架测试 |

### 方案 C：自建团队

按 6–8 人、6–8 个月估算：

| 角色 | 人数 | 月成本（万元/人，含社保/办公分摊） |
| --- | --- | --- |
| 产品/项目经理 | 1 | 2.5–3.5 |
| UI/UX | 1 | 2–3 |
| 小程序前端 | 1–2 | 2–3.5 |
| Flutter App | 1–2 | 2.5–4 |

- 自建适合长期迭代；如果只是一次性上线，外包通常更省现金

## 2. 上架与合规成本

### 2.1 固定/低额项目

| 项目 | 费用 | 说明 |
| --- | --- | --- |
| 微信小程序认证 | 300 元/年 | 企业主体认证 |
| Apple Developer Program | 约 700–800 元/年 | $99/年，汇率浮动 |
| 安卓应用商店开发者账号 | 0 元 | 华为/小米/OPPO/vivo/应用宝等，listing 免费 |
| 域名 | 50–100 元/年 | `.com`/`.cn` |
| SSL 证书 | 0 元 | 免费证书足够 |
| ICP 备案 | 0 元 | 通过云厂商提交，1–3 周 |
| APP 备案 | 0 元 | 工信部要求，应用商店上架前完成 |
| 公安联网备案 | 0 元 | 上线后 30 日内 |
| 软件著作权 | 0–1,000 元/件 | 自己申请免费但慢；代办加急约 300–1,000 元 |
| 隐私政策/用户协议/租赁协议 | 0.5–2 万 | 建议找律师审一遍 |

### 2.2 平台模式可能涉及的资质

| 资质 | 费用（代办） | 说明 |
| --- | --- | --- |
| ICP 经营许可证 | 1–3 万 | 通过互联网向用户收费/商家入驻平台，通常需要 |
| EDI 许可证 | 1.5–4 万 | 在线数据处理与交易处理，平台交易模式常见 |
| 等保二级测评 | 3–8 万 | 涉及大量个人信息/交易，部分应用商店或监管会要求 |
| 等保三级测评 | 8–20 万 | 用户量和数据敏感度更高时 |

> 平台抽佣、商家入驻、在线交易，大概率涉及 ICP/EDI；具体以当地通信管理局和要求为准。自营租赁是否必须办 EDI，需要提前咨询。ICP/EDI 通常要求注册资本 100 万、3 名员工社保等条件，办理周期 2–4 个月，建议和开发并行启动。

### 2.3 合规预算建议

| 方案 | 合规预算 |
| --- | --- |
| 只做小程序 + 自营租赁，先不开放商家入驻 | 1–5 万（软著、协议、备案、认证） |
| 平台模式（商家入驻/抽佣） | 5–15 万（含 ICP/EDI 代办，不含等保） |
| 平台 + 等保二级 | 10–25 万 |

## 4. 年度维护成本

| 项目 | 低配（万元/年） | 标准（万元/年） | 说明 |
| --- | --- | --- | --- |
| 云资源 | 2–4 | 5–12 | 用户/图片/订单增长后上升 |
| 第三方 API | 1–2 | 2–6 | 短信、IM、地图、审核、物流 |
| 技术维护 | 10–20 | 20–40 | 1 名兼职/外包，或 1 名全职 + 0.5 QA |
| 合规/证书/等保 | 1–3 | 3–8 | 年检、复测、协议更新 |
| 应用商店适配 | 1–3 | 2–5 | 系统版本、隐私规范、审核规则变化 |
| **合计** | **15–32** | **32–71** | 不含市场投放和业务人力 |

> 如果只有一个兼职维护，年度技术维护可以压到 10–15 万；但支付、库存、上架审核出问题时，响应会慢。建议至少保留 1 名熟悉业务的后端/全栈。

## 6. 钱主要花在哪

1. **库存与档期系统**：一物一码、按日锁档、防超卖、清洗状态，是租衣平台最容易被低估的部分。
2. **支付/押金/退款/分账**：涉及资金，测试和合规成本高。
3. **订单状态机与物流**：发货、签收、归还、质检、赔付，状态多、异常多。
4. **多端适配**：小程序、iOS、Android 的登录、支付、审核规则不同。
5. **上架合规**：ICP/EDI、APP 备案、软著、隐私、等保，时间和现金都不低。
6. **维护**：应用商店规则、支付接口、隐私政策每年都在变。

---

## 7. 省钱建议

1. **先小程序，后 App**：小程序获客和支付闭环最快，App 等复购/社区起来再做。
2. **跨端复用**：小程序用 Taro/uni-app，App 用 Flutter；一套后端 API。
3. **MVP 摄影先做“定金 + 人工派单”**：不做复杂排班、选片、精修交付系统。
4. **社区二期**：先做“目的地攻略 + 真实客片”，不做发帖/关注/创作者激励。
5. **能用 SaaS 就不自研**：IM、电子合同、物流查询、内容审核、地图、短信。
6. **押金用支付分/信用免押**：不要自建资金池，合规和开发都更轻。
7. **云资源从简**：MVP 2–4 核 8G 两台 + 云数据库足够，不要一上来上 K8s。
8. **留 15–20% 缓冲**：支付、库存、上架审核最容易超预算。

## 9. 最终建议

- **第一版预算**：准备 **30–60 万**，做小程序 + 商家端 + 后台 + 后端，4 个月内上线。
- **全端预算**：准备 **75–150 万**，做小程序 + iOS/Android + 社区，6–8 个月。
- **年度维护**：预留 **20–50 万/年**，不要只算开发费。
- **最容易超支的地方**：库存/押金/物流的异常流程、上架合规、App 审核反复。
- **最值得先做的**：把“选衣—支付—送达—归还—退押金”跑通，再谈 App 和社区。
