## 0. 优先级说明

| 级别 | 含义 | 处理方式 |
| --- | --- | --- |
| **P0** | MVP 必须有，缺失则交易/履约闭环不成立 | 首版必须上线 |
| **P1** | 上线后 1–3 个月补齐，显著影响体验/转化 | 第二迭代 |
| **P2** | 二期或验证后再做，避免过早投入 | 排入 Roadmap |

> 原则：**先闭环，再优化；先单城，再多城；先交易，再社区。**

### 6.2 开发顺序（建议 16 周）

| 阶段 | 周 | 内容 |
| --- | --- | --- |
| Sprint 0 | 1–2 | 需求确认、原型、UI、技术选型、商家签约 |
| Sprint 1 | 3–4 | 登录、城市、商品列表/详情、尺码、搜索 |
| Sprint 2 | 5–6 | 库存/档期、确认订单、支付、押金、地址 |
| Sprint 3 | 7–8 | 订单状态、物流、归还、退款、评价 |
| Sprint 4 | 9–10 | 摄影列表/详情/档期/IM/定金、商家端接单 |
| Sprint 5 | 11–12 | 商家端发货/归还/质检、后台订单/退款/分账 |

## 7. 关键验收标准

| 类别 | 标准 |
| --- | --- |
| 交易 | 微信支付成功率 ≥ 99%，支付回调幂等，重复支付可退 |
| 库存 | 同一实物件同一时段不可重复锁定，超卖 = 0 |
| 档期 | 租期含物流缓冲，发货/归还日期计算正确 |
| 押金 | 押金与租金分账，退款可追踪，3 个工作日内到账率 ≥ 98% |
| 订单 | 状态机不可逆错误为 0，超时任务自动触发 |
| 物流 | 发货/签收/归还节点可查，异常预警 |
| 摄影 | 档期锁定/释放正确，定金/尾款金额正确 |
| 权限 | 商家只能看自己的订单/库存；后台 RBAC 生效 |
| 安全 | 无越权、无敏感信息明文、支付签名校验 |
| 性能 | 首页首屏 ≤ 1.5s，核心 API P95 ≤ 300ms |
| 兼容 | iOS/Android 主流机型、微信最新版 |
| 合规 | 隐私政策、租赁协议、押金规则、退改规则齐全 |

## 8. 功能取舍建议

**必须做深**：

1. 商品详情（实拍、尺码、档期、押金、清洗）——决定转化和退货率；
2. 库存/档期——决定履约成败；
3. 订单状态与消息——决定客服成本；
4. 归还/押金/理赔——决定口碑和复购；
5. 商家履约工具——决定供给质量。

**可以后置**：

- 社区发帖、关注、创作者激励；
- 会员/储值；
- AI 试穿；
- 多城市调拨；
- 复杂营销玩法（拼团、分销）；

- 一开始就做 App；

- 允许商家私下加价/站外交易；
- 用虚假客片/刷单冲量。
